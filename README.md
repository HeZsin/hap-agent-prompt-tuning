# hap-agent-prompt-tuning

明道云 HAP 工作流 **AI Agent 节点提示词调优 Skill**。让任何人都能按一套固定流程，把 Agent 节点的工具调用从「频繁失败、反复重试」调成「一次成功、近零重试」。

> 适用于 Trae 等支持 Agent Skills 的 AI 编程工具。Skill 本身不是代码，而是一套给 AI 的执行规程。

## 解决什么问题

AI Agent 节点解析内容没问题，但工具调用频繁失败：字段名报错、附件格式错误、建出空记录、同一记录重复新建。根因几乎都在**参数结构**，不在模型能力。

本 Skill 的核心原则：**把「字段名、传值结构、失败即停」写成不可协商的硬规则，比反复描述业务逻辑更能提升工具调用成功率。**

实战效果（政务运维工单录入场景）：附件到建单 < 10 秒，工具轮次从 5-8 降到 2-3，近零重试。

## 五阶段流程

| 阶段 | 做什么 | 产出 |
|---|---|---|
| 1 明确任务 | 确认业务动作 / 涉及工作表 / 可用工具 | 一句话任务定义（需用户确认） |
| 2 采集元数据 | HAP MCP → hap-cli → 手动贴清单，三级降级 | 字段清单表（别名/ID/类型/必填/只读） |
| 3 平台预检 | 确认卡、必填默认值、执行者权限、查询条数、唯一性校验 | 平台侧配置清单 |
| 4 生成提示词 | 七段式骨架 + 传值映射 + 7 条硬约束 | 可直接粘贴的节点提示词 |
| 5 测试调优 | 5 个标准用例 + 报错对照定位 + 最小修改 | 验收：轮次 ≤ 3、近零重试、失败不产生空记录 |

## 安装

把本仓库克隆或下载后，将整个目录放入 skills 目录（目录名保持 `hap-agent-prompt-tuning`）：

```bash
# 项目级（仅当前项目生效）
git clone https://github.com/HeZsin/hap-agent-prompt-tuning.git <你的项目>/.trae/skills/hap-agent-prompt-tuning

# 全局（Trae CN，所有项目生效）
git clone https://github.com/HeZsin/hap-agent-prompt-tuning.git ~/.trae-cn/skills/hap-agent-prompt-tuning
```

元数据采集优先走 HAP MCP（`get_worksheet_structure` / `get_worksheet_field`），未配置 MCP 时自动降级到 hap-cli 或手动贴字段清单，**无 MCP 也能用**。

## 使用

安装后对 AI 说类似的话即可自动触发：

- 「帮我优化这个 AI Agent 节点的提示词」
- 「Agent 节点建单总是报字段无效」
- 「工作流 agent 建出了空记录，帮我调一下」

AI 会先和你确认任务定义，再采集字段、预检平台配置、生成提示词，最后陪你跑测试用例闭环。

## 文件结构

```
hap-agent-prompt-tuning/
├── SKILL.md                      # 触发条件、边界、五阶段流程、7 条硬约束
└── references/
    ├── 字段传值映射表.md          # 各字段类型传值形态 + 只读黑名单 + 查询筛选规则
    ├── 报错对照表.md              # 报错按 5 类定位（字段名/结构/权限/平台限制/超时）+ 诊断 runbook
    └── 提示词骨架.md              # 七段式可复制模板（示例已脱敏）
```

## 验证状态说明

传值映射表中 ✅ 为实测验证过的类型（文本/单选/日期/关联/附件），⚠️ 为常见默认写法（多选/人员/部门/数值/勾选/子表），首次在目标环境使用时 Skill 会要求跑最小用例确认。**欢迎提 Issue / PR 回写你环境里的实测结果**，让映射表越用越准。

## 边界

- 不处理工作流 JS/PY 代码块、发送 API 请求节点、集成中心开发。
- 平台侧操作（勾选工具、改表单配置）只给清单，由用户执行。
- 仓库内所有字段别名、域名、URL 均为脱敏示例。

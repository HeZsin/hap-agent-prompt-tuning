# 报错对照表与诊断 Runbook

用法：拿工具报错**原文**先匹配下表；匹配不到再按类别诊断。一次只改一处，改完重跑失败用例。

## 一、报错 → 原因 → 改法（按类别）

### A 类 · 字段名错误（改提示词里的字段清单）

| 报错特征 | 原因 | 改法 |
|---|---|---|
| 字段 `xxx` 无效 / 不存在 | 用了中文名或自造别名；或该字段没有别名 | 回阶段 2 重新采集，改用真实 alias 或字段 ID |
| 参数 fields 包含不存在的控件 [recordId] | 记录 ID 字段名写错 | 改为 `rowid` |
| 参数 fields 包含不存在的控件 [拼接/编号类字段] | 查询字段含只读黑名单字段 | 从查询字段里删掉（见映射表第二节） |

### B 类 · 参数结构错误（改提示词里的传值格式段）

| 报错特征 | 原因 | 改法 |
|---|---|---|
| contains/in 的 value 结构错误 | 传了字符串或空数组 | 改成非空数组 |
| 附件数据格式错误 | 键名写成 fileName/downloadUrl、没传数组、缺 type | 改 `name`/`url` 数组 + `"type":"1"` |
| 字段值格式/类型错误 | 单选传了数组、日期格式不对、多选形态不符 | 对照映射表逐类型修正；⚠️ 类型先跑最小用例确认 |
| URL 相关解析失败 | URL 带反引号或被换行截断 | 提示词声明 URL 用纯文本 |

### C 类 · 权限与校验（回阶段 3 平台预检，不是提示词问题）

| 报错特征 | 原因 | 改法 |
|---|---|---|
| 无权限 / permission denied | 工作流执行者对目标表无增改权限 | 换执行者或授权 |
| 必填字段不能为空（人员/部门） | AI 无法生成账号 ID | 表单配默认值，或提示词从查询结果取 ID |
| 字段值不能重复 | 唯一性校验命中已有记录 | 提示词写明按名称查回复用 `rowid`，不重复新建 |

### D 类 · 平台限制与流程错误

| 报错特征 | 原因 | 改法 |
|---|---|---|
| 工具未返回完整执行结果 / 空输出 | 前一步失败后仍继续执行 | 强化「失败即停」条款；检查是否已产生空记录并清理 |
| 查询「未匹配」但记录明明存在 | 返回条数限制 / 筛选字段不对 | 加精确筛选、限制条数；换有索引的入口字段 |
| 每条记录都弹确认卡 | 工具开了人工确认 | 平台侧关闭或只保留关键表 |

### E 类 · 超时与容量

| 报错特征 | 原因 | 改法 |
|---|---|---|
| 节点执行超时 | 单次处理量过大、工具轮次过多 | 拆小批量；压缩提示词流程步骤；减少不必要的查询 |
| 附件解析失败/超时 | 文件过大或格式不支持 | 限制文件大小；换支持的格式；先解析后建单分两轮 |

## 二、诊断 Runbook（匹配不到报错时）

1. **看失败发生在哪一步**：查询失败 → A/B 类优先；写入失败 → B/C 类优先；输出异常 → D 类。
2. **拿实际调用参数对照映射表**：让用户从工作流执行日志里复制该工具的入参 JSON，逐字段核对 id、value 形态、type。
3. **最小复现**：构造只含 1-2 个字段的最小写入用例，成功则逐步加字段，第一个失败字段即根因。
4. **区分提示词问题与平台问题**：同样的参数在表单/API 里也失败 → 平台配置（阶段 3）；只有 Agent 调用失败 → 提示词。
5. **禁止的操作**：凭猜测同时改多处；报错后让 Agent「重试直到成功」（会掩盖结构错误并产生脏数据）。
